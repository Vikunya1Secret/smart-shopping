# Реестр источников данных

**Проект:** Умный Шопинг
**Функция:** M3.1
**Связанные требования:** FR-2, FR-3, NFR-6, NFR-7
**Автор:** Клейн А.Н., проверка доступов: Ким Е.С.
**Статус:** черновик. Колонка «Проверено» заполняется только по факту проверки.

## 1. Цель

Определить, из каких источников система берёт предложения, как именно, с какими ограничениями и в каком порядке они подключаются. Для приёмки нужно минимум 3 источника на запрос.

## 2. Принцип выбора

1. Приоритет официальным API и партнёрским фидам.
2. Парсинг используется как дополнение и только с учётом правил площадки и закона.
3. Если реальный источник недоступен, на время разработки подключаем тестовый фид или мок-данные (тип `mock`), реальный источник подключаем по готовности.
4. Каждый источник подключается отдельным адаптером (NFR-6).

## 3. Кандидаты

| № | Источник | Способ получения | Что даёт | Ограничения и риски | Проверено | Приоритет |
|---|---|---|---|---|---|---|
| 1 | Яндекс Маркет | партнёрские фиды магазинов, публичный доступ для агрегатора не подтверждён | цены, наличие, продавцы | закрытость, доступ только партнёрам | не проверено | _заполнить_ |
| 2 | Price.ru | прайс-листы партнёров, публичный API не подтверждён | цены, магазины | доступ зависит от партнёрских условий | не проверено | _заполнить_ |
| 3 | Wildberries | публичный API для покупателей не подтверждён, у маркетплейсов обычно API для продавцов | цены, наличие, рейтинг | защита от парсинга, капчи, юридические ограничения | не проверено | _заполнить_ |
| 4 | Ozon | публичный API для покупателей не подтверждён | цены, наличие, рейтинг | защита от парсинга, капчи, юридические ограничения | не проверено | _заполнить_ |
| 5 | Магазины с открытым фидом YML/XML | выгрузка прайс-листа | цены, наличие | зависит от конкретного магазина | не проверено | _заполнить_ |
| 6 | Тестовый фид (mock) | собственные тестовые данные | любые нужные поля | не отражает реальный рынок | да (создаётся командой) | резерв |

Примечание: сведения о способах получения в таблице взяты из анализа аналогов в отчёте 1 и являются гипотезами до проверки.

## 4. Критерии оценки источника

| Критерий | Вопрос |
|---|---|
| Законность | разрешает ли площадка автоматический сбор данных |
| Стабильность | как часто меняется формат и защита |
| Полнота данных | есть ли цена, наличие, рейтинг, возврат, гарантия |
| Скорость | укладывается ли ответ в таймаут 5 секунд |
| Стоимость | бесплатно ли, есть ли лимиты запросов |
| Трудоёмкость | сколько дней займёт адаптер |

## 6. План подключения

| Неделя | Что подключаем |
|---|---|
| 2 | адаптеры 1–2 (реальные источники или мок), минимум 2 источника в выдаче |
| 3 | адаптер 3, итого минимум 3 источника |

## 7. Решение по итогам проверки

_Заполнить после проверки: какие источники выбраны, какие заменены тестовыми фидами._

## 8. Риски

- Блокировки и капчи при парсинге (см. `docs/risks/risk_register.md`, R1).
- Нет открытого API у части площадок (R2).
- Источник может изменить формат без предупреждения: адаптеры должны переживать сбой одного источника.
