# Правила приведения рейтинга продавца к единой шкале

**Проект:** Умный Шопинг
**Функция:** M8.1 (рейтинг продавца); связь с M8.3 (оценка надёжности, Should)
**Связанные требования:** FR-3, FR-15, критерий заказчика «рейтинг продавца в предложениях»
**Автор:** Клейн А.Н.
**Дата:** 23.11.2026
**Статус:** правила для реализации; значения «предложено» подлежат согласованию с бэкенд-разработчиком

## 1. Назначение

Разные площадки оценивают продавцов по разным шкалам и с разным числом отзывов. Чтобы рейтинги можно было сравнивать и использовать в индексе выгоды, их нужно привести к единой шкале и учесть надёжность оценки: 5,0 на трёх отзывах не равно 4,8 на тысяче.

## 2. Единая шкала

Рейтинг хранится как число от 0 до 5 с шагом 0,1. Исходное значение источника сохраняется в поле `seller_rating_raw` (см. `offer_data_spec.md`).

## 3. Приведение исходных шкал

| Шкала источника | Правило | Пример |
|---|---|---|
| от 1 до 5 (или от 0 до 5) | без изменений | 4,6 → 4,6 |
| от 1 до 10 | делим на 2 | 9,2 → 4,6 |
| от 1 до 100 | делим на 20 | 96 → 4,8 |
| процент положительных отзывов | умножаем на 5 и делим на 100 | 94% → 4,7 |
| «звёзды» и словесные оценки | таблица соответствия, согласуется для каждого источника отдельно | — |
| рейтинга нет | значение пусто (null) | — |

Значение за пределами 0–5 после приведения считается ошибкой данных: записывается в лог, рейтинг ставится пустым.

## 4. Учёт числа отзывов

Для индекса выгоды используется скорректированный рейтинг, который подтягивает оценки с малым числом отзывов к среднему значению:

```
скорректированный = (v / (v + m)) × R + (m / (v + m)) × C
```

| Обозначение | Значение |
|---|---|
| R | приведённый рейтинг продавца |
| v | число отзывов |
| m | порог доверия, 20 отзывов (предложено) |
| C | средний рейтинг, 4,0 (предложено) |

**Примеры**

| R | v | Расчёт | Скорректированный |
|---|---|---|---|
| 5,0 | 3 | (3/23) × 5,0 + (20/23) × 4,0 = 0,652 + 3,478 | 4,1 |
| 4,8 | 1 240 | (1240/1260) × 4,8 + (20/1260) × 4,0 = 4,724 + 0,064 | 4,8 |
| 4,5 | 40 | (40/60) × 4,5 + (20/60) × 4,0 = 3,000 + 1,333 | 4,3 |

**Особые случаи**
- Число отзывов неизвестно: используется приведённый рейтинг R без коррекции, в карточке помечается «мало данных».
- Число отзывов равно 0: рейтинг считается пустым (null).
- Рейтинг пуст: в индексе выгоды применяется нейтральное значение (см. `benefit_index_calibration.md`).

## 5. Отображение пользователю

| Что | Правило |
|---|---|
| В таблице | приведённый рейтинг R с одним знаком после запятой |
| В карточке | рейтинг, число отзывов, метка уровня |
| При v меньше 10 | пометка «мало отзывов» |
| Нет рейтинга | «нет данных» |

**Метки уровня (предложено)**

| Скорректированный рейтинг | Метка |
|---|---|
| 4,5 и выше | высокий |
| от 4,0 до 4,4 | хороший |
| от 3,5 до 3,9 | средний |
| ниже 3,5 | низкий |

## 6. Модель данных

Дополнения к сущности Offer:

| Поле | Тип | Описание |
|---|---|---|
| seller_rating | число | приведённый рейтинг 0–5 |
| seller_rating_raw | строка | исходное значение и шкала, например «96/100» |
| reviews_count | число | число отзывов, если известно |
| seller_rating_adjusted | число | скорректированный рейтинг для индекса |

## 7. Критерии приёмки

- [ ] Рейтинги из разных шкал приводятся к шкале 0–5
- [ ] Исходное значение сохраняется
- [ ] Рейтинг с малым числом отзывов корректируется
- [ ] Пустой рейтинг не превращается в 0
- [ ] Значения вне диапазона попадают в лог и не ломают выдачу
- [ ] В таблице и карточке рейтинг отображается по правилам раздела 5
