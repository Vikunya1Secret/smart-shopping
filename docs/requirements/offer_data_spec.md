# Спецификация данных предложения

**Проект:** Умный Шопинг
**Функции:** M3.2, M3.3
**Связанные требования:** FR-3, FR-4, FR-5
**Автор:** Клейн А.Н.
**Статус:** черновик, согласовать с бэкенд-разработчиком (сверить с таблицей Offer в схеме БД)

## 1. Назначение

Единый формат предложения, в который адаптеры приводят данные из любых источников. Благодаря ему таблица сравнения, индекс выгоды и склейка товаров работают независимо от того, откуда пришли данные.

## 2. Поля предложения

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| id | число | да | идентификатор предложения |
| product_id | число | да | идентификатор товара (после склейки) |
| source_id | число | да | идентификатор источника |
| seller_name | строка | да | название продавца или магазина |
| title | строка | да | название товара у продавца |
| article | строка | нет | артикул или модель, если есть |
| price | число (2 знака) | да | цена товара в рублях |
| currency | строка | да | код валюты после приведения, по умолчанию `RUB` |
| availability | перечисление | да | `in_stock`, `on_order`, `out_of_stock`, `unknown` |
| seller_rating | число | нет | рейтинг продавца по единой шкале |
| seller_rating_raw | строка | нет | исходное значение рейтинга источника |
| reviews_count | число | нет | число отзывов о продавце |
| url | строка | да | ссылка на товар у продавца |
| return_policy | строка | нет | условия возврата (FR-4) |
| warranty_months | число | нет | срок гарантии в месяцах (FR-4) |
| fetched_at | дата и время | да | когда данные получены, UTC, формат ISO 8601 |

Результат расчёта доставки (стоимость и срок) хранится отдельно в `DeliveryEstimate` и связан с предложением по `offer_id`.

## 3. Правила нормализации (M3.3)

| Что приводим | Правило |
|---|---|
| Валюта | все цены переводятся в рубли, исходная валюта и курс сохраняются в логе (предложено) |
| Цена | число с двумя знаками после запятой, без пробелов и символов валюты |
| Рейтинг продавца | приводится к шкале от 0 до 5 с шагом 0,1 (предложено, согласовать с формулой индекса выгоды) |
| Наличие | значения источника сопоставляются с четырьмя значениями перечисления |
| Отсутствующие данные | хранятся как пусто (null), а не как 0 или пустая строка |
| Единицы измерения | вес в граммах, размеры в миллиметрах, срок гарантии в месяцах |
| Дата и время | UTC, ISO 8601 |
| Текст | обрезаются лишние пробелы, единая кодировка UTF-8 |

**Пример приведения рейтинга:** источник отдаёт 96 из 100, нормализованное значение: 96 / 100 × 5 = 4,8.

## 4. Пример нормализованного предложения

```json
{
  "id": 1024,
  "product_id": 55,
  "source_id": 2,
  "seller_name": "Магазин X",
  "title": "Смартфон Model Y 256 ГБ",
  "article": "MODEL-Y-256",
  "price": 47990.00,
  "currency": "RUB",
  "availability": "in_stock",
  "seller_rating": 4.8,
  "seller_rating_raw": "96/100",
  "reviews_count": 1240,
  "url": "https://example.com/item/123",
  "return_policy": "Возврат в течение 14 дней",
  "warranty_months": 12,
  "fetched_at": "2026-11-05T10:15:00Z"
}
```

Данные в примере условные.

## 5. Проверки качества данных

- [ ] Все обязательные поля заполнены
- [ ] Цена больше нуля
- [ ] Рейтинг в диапазоне от 0 до 5 или пусто
- [ ] Значение `availability` из списка допустимых
- [ ] Ссылка начинается с `https://`
- [ ] Дата получения не старше срока актуальности кэша
